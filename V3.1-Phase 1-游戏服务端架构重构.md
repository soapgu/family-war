# V3.1 Phase 1 — 游戏服务端架构重构详细设计

## 1. 背景与目标

v1.0 时服务端游戏逻辑主要围绕石头剪子布实现，`gameManager.js` 和 `handler.js` 的设计天然偏向 1v1 RPS 流程。v2.0 引入算术，v3.0 引入默写后，服务端已经承载三种玩法：

- 石头剪子布：1v1 出招、三局两胜、平局重赛。
- 算术达人：全员抢答、答错等待、答对得分、5 分结算、机器人超时答题。
- 英文默写：全员抢答、TTS、Unsplash 图片、难度、填空、5 分结算、机器人超时答题。

当前主要问题不是功能不可用，而是架构开始变厚：

- `gameManager.js` 同时包含三种游戏规则。
- `handler.js` 同时包含 socket 事件注册、房间校验、游戏启动、结果广播、机器人定时器和大量玩法分支。
- 算术和默写有明显相似流程，但目前重复逻辑较多。
- 机器人自动作答定时器散落在 `handler.js` 中，后续继续扩展会越来越难维护。

本阶段目标：

```txt
Socket 层负责：收事件、校验房间、调用游戏服务、广播结果
GameManager 负责：统一生命周期入口、按 type 分发、记录历史
具体 GameMode 负责：各自玩法规则
RobotScheduler 负责：机器人定时器
RoomManager 负责：房间、玩家、角色、当前 game 引用
```

本阶段不追求“通用游戏框架”，只做贴合当前三种玩法的轻量 class 抽象。

## 2. 设计原则

### 2.1 保持客户端协议兼容

Phase 1 不主动修改现有 socket 事件名：

```txt
room:join
room:leave
role:select
role:deselect
game:setMode
game:challenge
game:move
game:answer
game:start
game:question
game:roundResult
game:matchResult
game:answerAck
game:error
```

可以新增字段，但不删除客户端正在依赖的字段。

### 2.2 RoomManager 不做大拆

`RoomManager` 当前职责仍然比较清晰：

- 创建/删除房间。
- 玩家加入/离开。
- 角色选择/释放。
- 房间状态广播。
- 保存当前 `room.game` 引用。

本阶段只允许小幅整理，例如：

- `isValidGameMode(mode)`
- `getSelectedPlayerIds(roomId)`
- `getPlayerList(roomId, playerIds)`
- `getHumanPlayerIds(roomId)`

不把复杂游戏生命周期塞进 `RoomManager`。

### 2.3 class 继承，但避免父类变成上帝类

最终 class 结构：

```txt
BaseGameMode
├── RpsGameMode
└── QuizGameMode
    ├── ArithmeticGameMode
    └── SpellingGameMode
```

原则：

- 三种游戏都真正需要的能力，放进 `BaseGameMode`。
- 算术和默写共享的抢答题机制，放进 `QuizGameMode`。
- 某个玩法独有的规则，留在自己的 GameMode 中。

不要为了继承而牺牲清晰度。

### 2.4 重构分阶段兼容

为了降低风险，`gameManager.js` 原有 public 方法可以先保留为兼容壳：

- `submitMove(roomId, socketId, choice)`
- `submitArithmeticAnswer(roomId, socketId, questionId, answer)`
- `submitSpellingAnswer(roomId, socketId, questionId, answer)`
- `generateQuestion(game)`
- `generateSpellingQuestion(game)`

内部逐步改为调用新的 `submitInput` / `createNextQuestion`。这样可以让旧测试继续作为护城河。

兼容壳不能简单透传新结构。新 GameMode 内部统一返回嵌套结构：

```js
{
  action: 'round_result',
  result: {
    winner,
    scores,
  },
}
```

但当前旧测试和旧 `handler.js` 仍然读取平铺字段：

```js
{
  action: 'round_result',
  winner,
  scores,
}
```

因此旧 public API 必须做 legacy result adapter：

```js
submitMove(roomId, socketId, choice) {
  const outcome = this.submitInput(roomId, socketId, { choice })
  return this.toLegacyResult(outcome)
}
```

这条是 Phase 1 的硬约束：**GameMode 内部可以使用新结构，兼容壳必须保持旧调用方返回格式不变**。

## 4. 核心数据模型

### 4.1 通用 Game State

所有游戏都包含：

```js
{
  // 游戏唯一 ID，仍可沿用当前 game_${Date.now()}_${roomId}
  id: 'game_...',

  // 房间 ID
  roomId: 'default',

  // 游戏类型：rps / arithmetic / spelling
  type: 'arithmetic',

  // 参与本局游戏的 socketId 列表，机器人使用固定 __robot__
  players: ['socketA', '__robot__'],

  // 当前轮次/题号
  round: 1,

  // 分数表
  scores: {
    socketA: 0,
    __robot__: 0,
  },

  // 历史记录，每种游戏的 item 结构不同
  history: [],

  // playing / match_end
  status: 'playing',
}
```

### 4.2 RPS Game State

```js
{
  ...baseGame,

  // 当前局双方出拳记录
  // 两边都出完后结算，并清空 moves
  moves: {
    socketA: 'rock',
  },
}
```

### 4.3 Arithmetic Game State

```js
{
  ...baseGame,

  // 当前题。答对结算后置空，下一题重新生成。
  currentQuestion: {
    questionId: 'q_...',
    expression: '35 + 24',
    correctAnswer: 59,
    round: 1,

    // Phase 2 会正式启用，Phase 1 可先预留
    timeLimitMs: 20000,
  },

  // 当前题每个玩家提交过的答案
  answeredThisRound: {
    socketA: 58,
  },
}
```

### 4.4 Spelling Game State

```js
{
  ...baseGame,

  // 默写难度
  difficulty: 'easy',

  // 本轮比赛已经用过的单词，避免短时间重复
  usedWords: ['library'],

  currentQuestion: {
    questionId: 'q_...',
    word: 'music room',
    wordLength: 10,
```

## 5. BaseGameMode 设计

`BaseGameMode` 是所有游戏模式的基类，只放真正通用的能力。

```js
/**
 * 所有游戏模式的基类。
 *
 * 设计目的：
 * 1. 提供通用 game state 创建逻辑。
 * 2. 提供 ranking / player list 等通用辅助方法。
 * 3. 定义子类需要实现的方法形状。
 *
 * 注意：
 * - 这里不使用 TypeScript abstract class。
 * - 原生 JS 中用“默认方法抛错”的方式模拟抽象方法。
 */
class BaseGameMode {
  constructor({ type, config = {}, roomManager }) {
    if (!type) throw new Error('Game mode type is required')

    // 当前游戏模式类型，例如 rps / arithmetic / spelling
    this.type = type

    // 当前模式的配置。后续 Phase 2 会从 server/config.js 注入更多配置。
    this.config = config

    // 注入 roomManager，便于需要时访问机器人 ID 或房间信息。
    this.roomManager = roomManager
  }

  /**
   * 创建所有游戏共享的基础状态。
   *
   * 子类通常先调用 createBaseGame，再追加自己的私有字段：
   * - RPS 追加 moves
   * - Quiz 类游戏追加 currentQuestion / answeredThisRound
   * - Spelling 追加 difficulty / usedWords
   */
  createBaseGame({ roomId, playerIds }) {
    return {
      id: `game_${Date.now()}_${roomId}`,
      roomId,
      type: this.type,
      players: [...playerIds],
      round: 1,
      scores: Object.fromEntries(playerIds.map((id) => [id, 0])),
      history: [],
      status: 'playing',
    }
  }

  /**
   * 创建具体游戏。
   * 子类必须实现。
   */
  createGame() {
    throw new Error(`${this.type}.createGame() not implemented`)
  }

  /**
   * 构建 game:start 事件 payload。
   * 子类必须实现，因为 RPS 和答题类游戏结构差异较大。
   */
  buildStartPayload() {
    throw new Error(`${this.type}.buildStartPayload() not implemented`)
  }

  /**
   * 处理玩家输入。
   *
   * RPS input: { choice }
   * Quiz input: { questionId, answer }
   */
  submitInput() {
    throw new Error(`${this.type}.submitInput() not implemented`)
  }

  /**
   * 构建发送给单个玩家的 game:roundResult payload。
   *
   * 注意：
   * - 这是 socket 对外 payload。
   * - 和 QuizGameMode.createRoundSettlement 的“规则层结算快照”不是一回事。
   */
  buildPlayerRoundResultPayload() {
    throw new Error(`${this.type}.buildPlayerRoundResultPayload() not implemented`)
  }

  /**
   * 构建 game:matchResult payload。
   * 子类必须实现。
   */
  buildMatchResultPayload() {
    throw new Error(`${this.type}.buildMatchResultPayload() not implemented`)
  }

  /**
   * 创建下一题。
   * RPS 没有题目，默认返回 null。
   */
  createNextQuestion() {
    return null
  }

  /**
   * 构建 game:question payload。
   * RPS 没有题目，默认返回 null。
   */
  buildQuestionPayload() {
    return null
  }

  /**
   * 处理机器人输入。
   * 默认为 null，表示当前模式无需机器人定时处理。
   */
  handleRobotInput() {
    return null
  }

  /**
   * 当前模式是否需要启动机器人定时器。
   * RPS 机器人出拳是即时行为，不走定时器。
   */
  shouldScheduleRobot() {
    return false
  }

  /**
   * 获取机器人自动作答延迟。
   * RPS 默认 0。
   */
  getRobotDelayMs() {
    return 0
  }

  /**
   * 获取胜利分数。
   * RPS 子类覆盖为 2。
   * 算术/默写默认 5。
   */
  getWinningScore() {
    return this.config.winningScore || 5
  }

  /**
   * 判断指定玩家是否已经赢得整场比赛。
   */
  isMatchEnded(game, playerId) {
    return (game.scores[playerId] || 0) >= this.getWinningScore()
  }

  /**
   * 构建排行榜。
   * 算术和默写结算页复用该结构。
   */
  buildRanking({ game, room }) {
    return [...game.players]
      .map((id) => ({
        playerId: id,
        nickname: room.players[id]?.nickname || id,
        score: game.scores[id] || 0,
      }))
      .sort((a, b) => b.score - a.score || a.playerId.localeCompare(b.playerId))
      .map((entry, index) => ({
        rank: index + 1,
        ...entry,
      }))
  }

  /**
   * 构建参与玩家列表。
   * 算术和默写的 game:start 需要完整玩家列表。
   */
  buildPlayerList({ game, room }) {
    return game.players.map((id) => ({
      id,
      nickname: room.players[id]?.nickname || id,
      role: room.players[id]?.role || null,
    }))
  }
}

module.exports = BaseGameMode
```

## 6. QuizGameMode 设计

`QuizGameMode` 是算术和默写的中间基类，承载“出题抢答类游戏”的共用流程。

共性包括：

- 有当前题 `currentQuestion`。
- 有当前题答题记录 `answeredThisRound`。
- 每人每题只能答一次。
- 答错返回 `waiting`，只给本人 `answerAck`。
- 答对加分，产生 `round_result`。
- 达到胜利分数后产生 `match_result`。
- 机器人超时后提交正确答案。

```js
const BaseGameMode = require('./BaseGameMode')

/**
 * 出题抢答类游戏基类。
 *
 * ArithmeticGameMode 和 SpellingGameMode 都继承它。
 * 它负责抢答流程，子类只负责：
 * - 如何生成题目
 * - 如何标准化答案
 * - 如何判断答案正确
 * - 如何构建题目/结果 payload
 */
class QuizGameMode extends BaseGameMode {
  createGame(params) {
    const game = this.createBaseGame(params)

    // 当前题，开局后由 createNextQuestion 填充。
    game.currentQuestion = null

    // 当前题已答玩家记录。
    game.answeredThisRound = {}

    return game
  }

  /**
   * 统一处理答题类游戏的玩家输入。
   */
  submitInput({ roomId, room, game, playerId, input }) {
    if (!room || !game || game.type !== this.type) {
      return { action: 'error', message: `${this.getDisplayName()}游戏不存在` }
    }

    if (game.status !== 'playing') {
      return { action: 'error', message: '比赛已结束' }
    }

    if (!game.currentQuestion || game.currentQuestion.questionId !== input.questionId) {
      return { action: 'error', message: '题目已过期' }
    }

    if (!game.players.includes(playerId)) {
      return { action: 'error', message: '你不是本局玩家' }
    }

    if (game.answeredThisRound[playerId] !== undefined) {
      return { action: 'error', message: '你已经回答过本题' }
    }

    // 交给子类做答案标准化：
    // - 算术：Number(answer)
    // - 默写：String(answer).trim()
    const normalizedAnswer = this.normalizeAnswer(input.answer)

    // 交给子类做合法性校验。
    const validation = this.validateAnswer(normalizedAnswer)
    if (validation?.error) {
      return validation
    }

    game.answeredThisRound[playerId] = normalizedAnswer

    // 答错：不进入下一题，等待其他玩家或机器人。
    if (!this.isCorrectAnswer(game.currentQuestion, normalizedAnswer)) {
      return {
        action: 'waiting',

        // handler 根据 ack 给当前 socket 发送 game:answerAck。
        ack: this.buildWrongAnswerAck({
          question: game.currentQuestion,
          answer: normalizedAnswer,
        }),
      }
    }

    // 答对：统一加分、写历史、判断是否结算。
    return this.applyCorrectAnswer({
      roomId,
      room,
      game,
      playerId,
      answer: normalizedAnswer,
    })
  }

  /**
   * 答对后的统一处理。
   */
  applyCorrectAnswer({ room, game, playerId }) {
    game.scores[playerId]++

    const settlement = this.createRoundSettlement({
      game,
      playerId,
    })

    game.history.push(settlement.historyItem)
    game.currentQuestion = null
    game.round++

    if (this.isMatchEnded(game, playerId)) {
      game.status = 'match_end'

      return {
        action: 'match_result',
        result: {
          gameType: this.type,
          matchWinner: playerId,
          scores: { ...game.scores },
          ranking: this.buildRanking({ game, room }),
          history: [...game.history],
          answeredBy: { ...game.answeredThisRound },
        },
      }
    }

    return {
      action: 'round_result',
      result: {
        ...settlement.result,
        scores: { ...game.scores },
        answeredBy: { ...game.answeredThisRound },
      },
    }
  }

  /**
   * 答题类游戏在当前题存在时需要机器人定时器。
   */
  shouldScheduleRobot({ game, robotId }) {
    return game.status === 'playing'
      && !!game.currentQuestion
      && game.players.includes(robotId)
  }

  /**
   * 答错 waiting 后的机器人调度意图。
   *
   * 默认不调整。
   * SpellingGameMode 会覆盖它：所有人类都答错后，如果剩余时间大于 5s，
   * 将机器人自动答题时间缩短到 5s。
   */
  getRobotScheduleAfterWaiting() {
    return null
  }

  /**
   * 机器人提交正确答案。
   * 机器人和真人走同一套 submitInput 流程，避免规则分叉。
   */
  handleRobotInput({ roomId, room, game, robotId, questionId }) {
    if (!game.currentQuestion || game.currentQuestion.questionId !== questionId) {
      return null
    }

    return this.submitInput({
      roomId,
      room,
      game,
      playerId: robotId,
      input: {
        questionId,
        answer: this.getRobotAnswer(game.currentQuestion),
      },
    })
  }

  /**
   * 子类覆盖：标准化答案。
   */
  normalizeAnswer(answer) {
    return answer
  }

  /**
   * 子类覆盖：校验答案是否合法。
   */
  validateAnswer() {
    return null
  }

  /**
   * 子类必须实现：判断答案是否正确。
   */
  isCorrectAnswer() {
    throw new Error(`${this.type}.isCorrectAnswer() not implemented`)
  }

  /**
   * 子类必须实现：构建答错 ack。
   */
  buildWrongAnswerAck() {
    throw new Error(`${this.type}.buildWrongAnswerAck() not implemented`)
  }

  /**
   * 子类必须实现：创建本轮结算快照。
   *
   * 注意：
   * - 这是玩法规则层的内部结算结果。
   * - 返回值通常包含 historyItem 和 result。
   * - 不直接等同于 socket 对外 payload。
   */
  createRoundSettlement() {

  }

  /**
   * 子类必须实现：机器人正确答案。
   */

    throw new Error(`${this.type}.getRobotAnswer() not implemented`)
  }

  /**
   * 子类可覆盖：中文展示名，用于错误消息。
   */
  getDisplayName() {
    return this.type
  }
}
```

## 7. RpsGameMode 设计

RPS 不继承 `QuizGameMode`，直接继承 `BaseGameMode`。

```js
const BaseGameMode = require('./BaseGameMode')

const CHOICES = ['rock', 'paper', 'scissors']

/**
 * 石头剪子布游戏模式。
 *
 * 特点：
 * - 1v1 对战。
 * - 双方都出拳后结算一轮。
 * - 平局不加分，但会写入历史。
 * - 先到 2 分者胜。
 * - 机器人对手时，机器人即时随机出拳，不走定时器。
 */
class RpsGameMode extends BaseGameMode {
  constructor(deps) {
    super({
      ...deps,
      type: 'rps',
    })
  }

  createGame(params) {
    const game = this.createBaseGame(params)

    // 当前局双方出拳记录。
    game.moves = {}

    return game
  }

  /**
   * RPS 的 game:start 是单人视角：
   * 每个玩家收到自己的 opponent。
   */
  buildStartPayload({ game, room, playerId }) {
    const opponentId = game.players.find((id) => id !== playerId)
    const opponent = room.players[opponentId]

    return {
      gameType: this.type,
      opponent: {
        id: opponentId,
        nickname: opponent?.nickname || opponentId,
        role: opponent?.role,
      },
      round: game.round,
    }
  }

  /**
   * 处理玩家出拳。
   */
  submitInput({ room, game, playerId, input }) {
    const choice = input.choice

    if (game.status === 'match_end') {
      return { action: 'error', message: '比赛已结束' }
    }

    if (!game.players.includes(playerId)) {
      return { action: 'error', message: '你不是本局玩家' }
    }

    if (!this.isValidChoice(choice)) {
      return { action: 'error', message: '无效的出拳' }
    }

    if (game.moves[playerId]) {
      return { action: 'error', message: '你已经出过拳了' }
    }

    game.moves[playerId] = choice

    const [p1, p2] = game.players

    // 只收到一方出拳时，等待对手。
    if (!game.moves[p1] || !game.moves[p2]) {
      return {
        action: 'waiting',
        reason: 'waiting_opponent',
      }
    }

    return this.applyRoundResult({ room, game })
  }

  /**
   * 双方都出拳后的结算。
   */
  applyRoundResult({ game }) {
    const [p1, p2] = game.players
    const currentRound = game.round
    const result = this.getChoiceResult(game.moves[p1], game.moves[p2])

    let roundWinner = null

    if (result === 'player1') {
      game.scores[p1]++
      roundWinner = p1
    } else if (result === 'player2') {
      game.scores[p2]++
      roundWinner = p2
    } else {
      roundWinner = 'draw'
    }

    const historyItem = {
      round: currentRound,
      moves: { ...game.moves },
      winner: roundWinner,
    }

    game.history.push(historyItem)
    game.moves = {}

    const p1Wins = game.scores[p1] || 0
    const p2Wins = game.scores[p2] || 0
    const winningScore = this.getWinningScore()

    if (p1Wins >= winningScore || p2Wins >= winningScore) {
      const matchWinner = p1Wins >= winningScore ? p1 : p2
      game.status = 'match_end'

      return {
        action: 'match_result',
        result: {
          gameType: this.type,
          matchWinner,
          scores: { ...game.scores },
          history: [...game.history],
        },
      }
    }

    game.round++

    return {
      action: 'round_result',
      result: {
        gameType: this.type,
        round: currentRound,
        winner: roundWinner,
        moves: historyItem.moves,
        scores: { ...game.scores },
      },
    }
  }

  /**
   * 机器人出拳。
   *
   * RPS 机器人是即时行为：
   * handler 在发现 waiting_opponent 且对手是机器人时调用。
   */
  handleRobotInput({ roomId, room, game, robotId }) {
    return this.submitInput({
      roomId,
      room,
      game,
      playerId: robotId,
      input: {
        choice: this.randomChoice(),
      },
    })
  }

  /**
   * RPS 轮结果是每人视角。
   */
  buildPlayerRoundResultPayload({ game, result, playerId }) {
    const [a, b] = game.players
    const opponentId = playerId === a ? b : a

    return {
      round: result.round,
      winner: result.winner,
      yourMove: result.moves[playerId],
      oppMove: result.moves[opponentId],
      scores: result.scores,
    }
  }

  buildMatchResultPayload({ result }) {
    return {
      gameType: this.type,
      matchWinner: result.matchWinner,
      scores: result.scores,
      history: result.history,
    }
  }

  getWinningScore() {
    return this.config.winningScore || 2
  }

  isValidChoice(choice) {
    return CHOICES.includes(choice)
  }

  randomChoice() {
    return CHOICES[Math.floor(Math.random() * CHOICES.length)]
  }

  /**
   * 返回 player1 / player2 / draw。
   */
  getChoiceResult(move1, move2) {
    if (move1 === move2) return 'draw'
    if (
      (move1 === 'rock' && move2 === 'scissors') ||
      (move1 === 'scissors' && move2 === 'paper') ||
      (move1 === 'paper' && move2 === 'rock')
    ) return 'player1'
    return 'player2'
  }
}
```

```js
const QuizGameMode = require('./QuizGameMode')

/**
 * 算术达人游戏模式。

 * 继承 QuizGameMode：

  constructor(deps) {

      // Phase 2 正式使用。Phase 1 可以先下发或预留。

      round: game.round,
      firstQuestion: this.buildQuestionPayload({ question: firstQuestion }),
    }
  }

   * 算术 game:question payload。
   *
   * 注意：不能下发 correctAnswer。
   */

    return {
      questionId: question.questionId,
      expression: question.expression,
      round: question.round,
      timeLimitMs: question.timeLimitMs,
    }
  }

  normalizeAnswer(answer) {
    return Number(answer)
  }

  validateAnswer(answer) {
    if (!Number.isFinite(answer)) {
      return { action: 'error', message: '答案必须是数字' }
    }
    return null
  }

  isCorrectAnswer(question, answer) {
    return answer === question.correctAnswer
  }

      questionId: question.questionId,
      correct: false,
      correctAnswer: question.correctAnswer,
      expression: question.expression,
      yourAnswer: answer,
    }

   * 创建本轮结算快照。
   *
   * 这里处理的是“玩法规则层”的结算数据：
   * - historyItem：写入 game.history
   * - result：交给 QuizGameMode 扩展 scores / answeredBy 后继续流转
   *
   * 它不是 socket payload；socket payload 由 buildPlayerRoundResultPayload 构建。
   */
  createRoundSettlement({ game, playerId }) {
    const q = game.currentQuestion

    return {
      historyItem: {
        round: q.round,
        questionId: q.questionId,
        expression: q.expression,
        correctAnswer: q.correctAnswer,
        winner: playerId,
        answeredBy: { ...game.answeredThisRound },
      },
      result: {
        gameType: this.type,
        round: q.round,
        questionId: q.questionId,
        expression: q.expression,
        correctAnswer: q.correctAnswer,
        winner: playerId,
      },
    }
  }

  /**
   * 构建算术 game:roundResult 的玩家视角 payload。
   *
   * yourAnswer 是每个玩家自己的视角。
   */
  buildPlayerRoundResultPayload({ result, playerId }) {
    return {
      gameType: this.type,
      round: result.round,
      questionId: result.questionId,
      expression: result.expression,
      correctAnswer: result.correctAnswer,
      yourAnswer: result.answeredBy?.[playerId],
      winner: result.winner,
      scores: result.scores,
    }
  }

  buildMatchResultPayload({ result }) {
    return {
      gameType: this.type,
      matchWinner: result.matchWinner,
      scores: result.scores,
      ranking: result.ranking,
      history: result.history,
    }
  }

  getRobotAnswer(question) {
    return question.correctAnswer
  }

  getTimeLimitMs() {
    return this.config.questionTimeLimitMs || 20000
  }

  getRobotDelayMs({ game }) {
    return this.config.robotAnswerDelayMs || this.getTimeLimitMs({ game })
  }

  /**
   * 迁移现有 generateArithmeticQuestion 逻辑。
   *
   * 约束：
   * - 支持 + / -
   * - 结果保持在 0-100
   */
  generateArithmeticQuestion() {
    const op = Math.random() < 0.5 ? '+' : '-'
    let a, b, correctAnswer

    if (op === '+') {
      a = Math.floor(Math.random() * 101)
      b = Math.floor(Math.random() * (100 - a + 1))
      correctAnswer = a + b
    } else {
      a = Math.floor(Math.random() * 101)
      b = Math.floor(Math.random() * (a + 1))
      correctAnswer = a - b
    }

    return {
      expression: `${a} ${op} ${b}`,
      correctAnswer,
    }
  }
}
```

```js
class SpellingGameMode extends QuizGameMode {

      matchWinner: result.matchWinner,
      scores: result.scores,
      ranking: result.ranking,
      history: result.history,
    }
  }

  getRobotAnswer(question) {
    return question.word
  }

  getTimeLimitMs({ game }) {
    const difficulty = game.difficulty || 'easy'
    return this.config.difficulties?.[difficulty]?.questionTimeLimitMs || 40000
  }

  getRobotDelayMs({ game }) {
    const difficulty = game.difficulty || 'easy'
    const conf = this.config.difficulties?.[difficulty]
    return conf?.robotAnswerDelayMs || this.getTimeLimitMs({ game })
  }

  /**
   * 默写特殊体验：
   *
   * 当前所有人类玩家都已经答错时，不再让玩家等完整倒计时。
   * 如果机器人剩余作答时间还超过 5s，就缩短为 5s。
   *
   * 注意：
   * - GameMode 只返回“调度意图”。
   * - 真正查询剩余时间和重设 setTimeout 由 robotScheduler 完成。
   */
  getRobotScheduleAfterWaiting({ allHumansAnswered }) {
    if (!allHumansAnswered) return null

    return {
      action: 'accelerate',
      delayMs: 5000,
      onlyIfRemainingGreaterThanMs: 5000,
    }
  }

  /**
   * 从启用词库中取一个未使用单词。
   * 如果全部用完，则清空 usedWords 重新开始。
   */
  pickWord(game) {
    const activeWords = this.wordBank.getActiveWords()
      .filter((word) => typeof word === 'string' && word.length > 0)

    if (activeWords.length === 0) {
      throw new Error('当前没有可用的默写单词，请先配置词库')
    }

    let available = activeWords.filter((word) => !game.usedWords.includes(word))
    if (available.length === 0) {
      game.usedWords = []
      available = activeWords
    }

    const word = available[Math.floor(Math.random() * available.length)]
    game.usedWords.push(word)

    return word
  }

  /**
   * 根据难度生成填空。
   *
   * easy: 暴露 ceil(50%) 个字母
   * normal: 暴露 1-2 个字母
   * hard: 全部隐藏
   *
   * 空格统一显示为 ·。
   */
  generateBlanks(word, difficulty) {
    const chars = word.split('')
    const letterIndices = chars
      .map((ch, index) => (ch !== ' ' ? index : -1))
      .filter((index) => index >= 0)

    let showCount
    if (difficulty === 'easy') {
      showCount = Math.ceil(letterIndices.length * 0.5)
    } else if (difficulty === 'normal') {
      showCount = Math.min(letterIndices.length, 1 + Math.floor(Math.random() * 2))
    } else {
      showCount = 0
    }

    const positions = [...letterIndices]
    for (let i = 0; i < showCount; i++) {
      const j = i + Math.floor(Math.random() * (positions.length - i))
      ;[positions[i], positions[j]] = [positions[j], positions[i]]
    }

    const shownSet = new Set(positions.slice(0, showCount))

    return chars.map((ch, index) => {
      if (ch === ' ') return '·'
      return shownSet.has(index) ? ch : '_'
    }).join(' ')
  }
}
```

## 10. gameRegistry 设计

`gameRegistry` 负责创建并管理 GameMode 实例。

使用实例而不是静态方法的原因：

```js

/**
 * Phase 1 默认游戏配置。
 *
 * 当前 server/config.js 还没有 config.games 结构。
 * 因此 gameRegistry 必须自己提供兜底，不能直接读取 deps.config.games.rps。
 *
 * Phase 2 做倒计时配置统一时，可以把这些默认值搬进 server/config.js。
 */
const DEFAULT_GAME_CONFIG = {
  rps: {
    winningScore: 2,
  },
  arithmetic: {
    winningScore: 5,
    questionTimeLimitMs: 20000,
    robotAnswerDelayMs: 20000,
  },
  spelling: {
    winningScore: 5,
    difficulties: {
      easy: {
        questionTimeLimitMs: 40000,
        robotAnswerDelayMs: 40000,
      },
      normal: {
        questionTimeLimitMs: 30000,
        robotAnswerDelayMs: 30000,
      },
      hard: {
        questionTimeLimitMs: 20000,
        robotAnswerDelayMs: 20000,
      },
    },
  },
}

/**
 * 合并游戏配置。
 *
 * 这里不用简单浅合并 spelling.difficulties，
 * 否则只覆盖 normal 时可能丢掉 easy/hard 默认值。
 */
function resolveGameConfig(config = {}) {
  const custom = config.games || {}

  return {
    rps: {
      ...DEFAULT_GAME_CONFIG.rps,
      ...(custom.rps || {}),
    },
    arithmetic: {
      ...DEFAULT_GAME_CONFIG.arithmetic,
      ...(custom.arithmetic || {}),
    },
    spelling: {
      ...DEFAULT_GAME_CONFIG.spelling,
      ...(custom.spelling || {}),
      difficulties: {
        easy: {
          ...DEFAULT_GAME_CONFIG.spelling.difficulties.easy,
          ...(custom.spelling?.difficulties?.easy || {}),
        },
        normal: {
          ...DEFAULT_GAME_CONFIG.spelling.difficulties.normal,
          ...(custom.spelling?.difficulties?.normal || {}),
        },
        hard: {
          ...DEFAULT_GAME_CONFIG.spelling.difficulties.hard,
          ...(custom.spelling?.difficulties?.hard || {}),
        },
      },
    },
  }
}

/**
 * 创建游戏模式注册表。
 *
 * deps 示例：
 * {
 *   config,
 *   roomManager,
 *   wordBank,
 *   unsplashClient,
 * }
 */
function createGameRegistry(deps) {
  const gamesConfig = resolveGameConfig(deps.config)

  const modes = {
    rps: new RpsGameMode({
      ...deps,
      config: gamesConfig.rps,
    }),

    arithmetic: new ArithmeticGameMode({
      ...deps,
      config: gamesConfig.arithmetic,
    }),

    spelling: new SpellingGameMode({
      ...deps,
      config: gamesConfig.spelling,
    }),
  }

  return {
    /**
     * 获取指定游戏模式实例。
     */
    get(type) {
      const mode = modes[type]
      if (!mode) throw new Error(`Unsupported game type: ${type}`)
      return mode
    },

    /**
     * 判断是否支持某个游戏模式。
     * RoomManager.setGameMode 后续可以复用它，避免白名单写两份。
     */
    has(type) {
      return !!modes[type]
    },

    /**
     * 获取所有支持的游戏类型。
     */
    list() {
      return Object.keys(modes)
    },
  }
}

module.exports = createGameRegistry
```

### 11.2 示例代码

```js
/**
 * 游戏生命周期管理器。
 *
 * 负责：
 * - 创建游戏。
 * - 根据 game.type 分发到对应 GameMode。
 * - 记录 match history。
 *
 * 不负责：
 * - 具体玩法规则。
 * - socket 广播。
 * - 机器人定时器。
 */
class GameManager {
  constructor({ roomManager, gameRegistry }) {
    this.roomManager = roomManager
    this.gameRegistry = gameRegistry
    this.matchHistory = []
  }

  createGame(roomId, playerIds, type = 'rps', options = {}) {
    const room = this.roomManager.getRoom(roomId)
    const mode = this.gameRegistry.get(type)

    const game = mode.createGame({
      roomId,
      playerIds,
      room,
      ...options,
    })

    this.roomManager.setGame(roomId, game)
    return game
  }

  getGame(roomId) {
    return this.roomManager.getRoom(roomId)?.game || null
  }

  /**
   * 创建下一题。
   * RPS 返回 null。
   */
  createNextQuestion(roomId) {
    const room = this.roomManager.getRoom(roomId)
    const game = room?.game
    if (!game) return null

    const mode = this.gameRegistry.get(game.type)
    return mode.createNextQuestion({ room, game })
  }

  /**
   * 统一提交玩家输入。
   *
   * RPS input: { choice }
   * Arithmetic input: { questionId, answer }
   * Spelling input: { questionId, answer }
   */
  submitInput(roomId, playerId, input) {
    const room = this.roomManager.getRoom(roomId)
    const game = room?.game

    if (!room || !game) {
      return { action: 'error', message: '游戏不存在' }
    }

    const mode = this.gameRegistry.get(game.type)
    const result = mode.submitInput({
      roomId,
      room,
      game,
      playerId,
      input,
    })

    if (result.action === 'match_result') {
      this.recordMatchHistory({ room, game, result: result.result })
    }

    return result
  }

  buildStartPayload(roomId, playerId, firstQuestion) {
    const room = this.roomManager.getRoom(roomId)
    const game = room?.game
    const mode = this.gameRegistry.get(game.type)

    return mode.buildStartPayload({
      room,
      game,
      playerId,
      firstQuestion,
    })
  }

  buildQuestionPayload(roomId, question) {
    const game = this.getGame(roomId)
    const mode = this.gameRegistry.get(game.type)

    return mode.buildQuestionPayload({
      game,
      question,
    })
  }

  buildPlayerRoundResultPayload(roomId, playerId, result) {
    const room = this.roomManager.getRoom(roomId)
    const game = room?.game
    const mode = this.gameRegistry.get(game.type)

    return mode.buildPlayerRoundResultPayload({
      room,
      game,
      playerId,
      result,
    })
  }

  buildMatchResultPayload(roomId, playerId, result) {
    const room = this.roomManager.getRoom(roomId)
    const game = room?.game
    const mode = this.gameRegistry.get(game.type)

    return mode.buildMatchResultPayload({
      room,
      game,
      playerId,
      result,
    })
  }

  handleRobotInput(roomId, questionId) {
    const room = this.roomManager.getRoom(roomId)
    const game = room?.game
    if (!game) return null

    const mode = this.gameRegistry.get(game.type)

    return mode.handleRobotInput({
      roomId,
      room,
      game,
      robotId: this.roomManager.ROBOT_ID,
      questionId,
    })
  }

  shouldScheduleRobot(roomId) {
    const room = this.roomManager.getRoom(roomId)
    const game = room?.game
    if (!game) return false

    const mode = this.gameRegistry.get(game.type)
    return mode.shouldScheduleRobot({
      room,
      game,
      robotId: this.roomManager.ROBOT_ID,
    })
  }

  getRobotDelayMs(roomId) {
    const room = this.roomManager.getRoom(roomId)
    const game = room?.game
    if (!game) return 0

    const mode = this.gameRegistry.get(game.type)
    return mode.getRobotDelayMs({ room, game })
  }

  /**
   * 获取答错 waiting 后的机器人调度意图。
   *
   * 当前主要用于 Spelling：
   * 所有人类都答错后，将机器人剩余答题时间缩短到 5s。
   */
  getRobotScheduleAfterWaiting(roomId) {
    const room = this.roomManager.getRoom(roomId)
    const game = room?.game
    if (!game) return null

    const mode = this.gameRegistry.get(game.type)
    return mode.getRobotScheduleAfterWaiting({
      room,
      game,
      allHumansAnswered: this.areAllHumansAnswered(roomId),
    })
  }

  /**
   * 记录比赛历史。
   *
   * 可以保留当前 history 字段结构，避免管理后台破坏。
   * RPS 没有 ranking，因此 ranking 只能在 result.ranking 存在时写入。
   */
  recordMatchHistory({ room, game, result }) {
    const record = {
      id: game.id,
      roomId: game.roomId,
      type: game.type,
      players: [...game.players],
      playerNames: Object.fromEntries(
        game.players.map((id) => [id, room?.players[id]?.nickname || id])
      ),
      scores: { ...result.scores },
      matchWinner: result.matchWinner,
      matchWinnerName: room?.players[result.matchWinner]?.nickname || result.matchWinner,
      history: [...result.history],
      endedAt: Date.now(),
    }

    // 算术/默写有 ranking；RPS 沿用旧结构，不写 undefined ranking。
    if (result.ranking) {
      record.ranking = result.ranking
    }

    this.matchHistory.push(record)
  }

  getMatchHistory() {
    return this.matchHistory
  }

  /**
   * 取消游戏。
   * 离房、断线等场景可调用。
   */
  cancelGame(roomId) {
    this.roomManager.clearGame(roomId)
  }

  /**
   * 检查所有人类玩家是否都已作答。
   * 算术/默写仍可使用该逻辑提前触发机器人或进入等待边界处理。
   */
  areAllHumansAnswered(roomId) {
    const game = this.getGame(roomId)
    if (!game || !game.answeredThisRound) return false

    const humanIds = game.players.filter((id) => id !== this.roomManager.ROBOT_ID)
    return humanIds.length > 0 && humanIds.every((id) => game.answeredThisRound[id] !== undefined)
  }

  // ==================== 兼容壳：降低迁移风险 ====================

  /**
   * 将新 GameMode 的嵌套返回结构转换为旧 public API 的平铺结构。
   *
   * 新结构：
   * { action: 'round_result', result: { winner, scores } }
   *
   * 旧结构：
   * { action: 'round_result', winner, scores }
   *
   * 旧单元测试、旧 handler 在迁移完成前都依赖平铺字段。
   */
  toLegacyResult(outcome) {
    if (!outcome || !outcome.result) {
      return outcome
    }

    return {
      action: outcome.action,
      ...outcome.result,
    }
  }

  submitMove(roomId, socketId, choice) {
    const outcome = this.submitInput(roomId, socketId, { choice })
    return this.toLegacyResult(outcome)
  }

  submitArithmeticAnswer(roomId, socketId, questionId, answer) {
    const outcome = this.submitInput(roomId, socketId, { questionId, answer })
    return this.toLegacyResult(outcome)
  }

  submitSpellingAnswer(roomId, socketId, questionId, answer) {
    const outcome = this.submitInput(roomId, socketId, { questionId, answer })
    return this.toLegacyResult(outcome)
  }
}
```

## 12. RobotScheduler 设计

`RobotScheduler` 从 `handler.js` 中抽出机器人定时器逻辑。

目标：

- 统一 `setTimeout` 创建和清理。
- 防止下一题、答对、赛果、离房、断线时旧 timer 残留。
- 支持默写“所有人类答错后缩短到 5s”的重新调度。
- Scheduler 不直接懂玩法规则。
- Scheduler 不直接构造 socket payload，而是把机器人结果回调给 handler 统一处理。

```js
/**
 * 创建机器人自动作答调度器。
 *
 * Scheduler 只负责定时器：
 * - 什么时候启动
 * - 什么时候清理
 * - 到点后调用 gameManager.handleRobotInput
 *
 * 真正广播仍交给 handler 的 onRobotResult 回调。
 */
function createRobotScheduler({
  gameManager,
  onRobotResult,
}) {
  const timers = new Map()
  const timerEndAt = new Map()

  function clear(roomId) {
    if (timers.has(roomId)) {
      clearTimeout(timers.get(roomId))
      timers.delete(roomId)
    }
    timerEndAt.delete(roomId)
  }

  function schedule(roomId, questionId) {
    clear(roomId)

    if (!gameManager.shouldScheduleRobot(roomId)) {
      return
    }

    const delayMs = gameManager.getRobotDelayMs(roomId)
    if (!delayMs || delayMs <= 0) {
      return
    }

    timerEndAt.set(roomId, Date.now() + delayMs)

    const timer = setTimeout(() => {
      timers.delete(roomId)
      timerEndAt.delete(roomId)

      const result = gameManager.handleRobotInput(roomId, questionId)
      if (result) {
        onRobotResult(roomId, result)
      }
    }, delayMs)

    timers.set(roomId, timer)
  }

  function getEndAt(roomId) {
    return timerEndAt.get(roomId) || null
  }

  function getRemainingMs(roomId) {
    const endAt = getEndAt(roomId)
    return endAt ? Math.max(0, endAt - Date.now()) : 0
  }

  /**
   * 将某个房间的机器人作答时间提前。
   *
   * 用于默写特殊逻辑：
   * - 所有人类都已答错
   * - 当前剩余时间还大于 5s
   * - 则把机器人作答时间改为 5s 后
   */
  function accelerate(roomId, questionId, delayMs, options = {}) {
    const remaining = getRemainingMs(roomId)
    const threshold = options.onlyIfRemainingGreaterThanMs || 0

    if (threshold > 0 && remaining <= threshold) {
      return false
    }

    clear(roomId)
    timerEndAt.set(roomId, Date.now() + delayMs)

    const timer = setTimeout(() => {
      timers.delete(roomId)
      timerEndAt.delete(roomId)

      const result = gameManager.handleRobotInput(roomId, questionId)
      if (result) {
        onRobotResult(roomId, result)
      }
    }, delayMs)

    timers.set(roomId, timer)
    return true
  }

  function clearAll() {
    for (const roomId of timers.keys()) {
      clear(roomId)
    }
  }

  return {
    schedule,
    accelerate,
    clear,
    clearAll,
    getEndAt,
    getRemainingMs,
  }
}

module.exports = createRobotScheduler
```

## 13. handler.js 重构方向

`handler.js` 目标是变薄，成为 socket 编排层。

```js
socket.on('game:challenge', ({ mode = 'rps', targetId, roomId } = {}) => {
  const rid = roomId || currentRoom

  // 1. 基础房间校验。
  const room = roomManager.getRoom(rid)
  if (!room) {
    socket.emit('game:error', { message: '房间不存在' })
    return
  }

  // 2. 确保客户端请求 mode 和房间当前 mode 一致。
  if (mode !== room.gameMode) {
    socket.emit('game:error', { message: '游戏模式已变更，请返回房间重试' })
    return
  }

  // 3. 如果已有 playing 游戏，拒绝开局。
  if (room.game && room.game.status === 'playing') {
    socket.emit('game:error', { message: '当前房间已有进行中的比赛' })
    return
  }

  // 4. 非 playing 旧 game 可以清理。
  if (room.game) {
    clearGameAndRobotSchedule(rid)
  }

  // 5. 根据 mode 决定参与玩家。
  //    RPS 使用 challenger + targetId。
  //    算术/默写使用所有已选角色玩家。
  const playerIds = resolvePlayerIds({ mode, room, socket, targetId })

  // 6. 创建游戏。
  const game = gameManager.createGame(rid, playerIds, mode, {
    difficulty: room.spellingDifficulty,
  })

  // 7. 答题类游戏生成首题，RPS 返回 null。
  const firstQuestion = gameManager.createNextQuestion(rid)

  // 8. 给每个玩家发送 game:start。
  game.players.forEach((playerId) => {
    io.to(playerId).emit(
      'game:start',
      gameManager.buildStartPayload(rid, playerId, firstQuestion)
    )
  })

  // 9. 如果需要机器人定时器，启动。
  if (firstQuestion) {
    robotScheduler.schedule(rid, firstQuestion.questionId)
  }

  // 10. 广播房间状态。
  roomManager.broadcastRoomState(rid, io)
})
```

### 13.5 统一处理输入伪代码

```js
function handleGameInput(socket, input) {
  const rid = currentRoom
  if (!rid) {
    socket.emit('game:error', { message: '请先加入房间' })
    return
  }

  const game = gameManager.getGame(rid)
  if (!game) {
    socket.emit('game:error', { message: '没有进行中的比赛' })
    return
  }

  const result = gameManager.submitInput(rid, socket.id, input)

  if (result.action === 'error') {
    socket.emit('game:error', { message: result.message })
    return
  }

  if (result.action === 'waiting') {
    // RPS 等待对手，如果对手是机器人，需要即时触发机器人出拳。
    if (game.type === 'rps' && result.reason === 'waiting_opponent' && game.players.includes(ROBOT_ID)) {
      const robotResult = gameManager.handleRobotInput(rid)
      if (robotResult) handleGameResult(rid, robotResult)
      return
    }

    // 算术/默写答错，只给本人 ACK。
    if (result.ack) {
      socket.emit('game:answerAck', result.ack)
    } else {
      socket.emit('game:waiting')
    }

    // 默写的特殊规则由 GameMode 返回“调度意图”：
    // 当所有人类玩家都已答错，且机器人剩余等待时间仍大于 5 秒时，
    // 将机器人作答时间缩短为 5 秒。GameMode 不直接操作 setTimeout。
    const scheduleIntent = gameManager.getRobotScheduleAfterWaiting(rid)
    if (scheduleIntent?.action === 'accelerate') {
      robotScheduler.accelerate(
        rid,
        input.questionId,
        scheduleIntent.delayMs,
        {
          onlyIfRemainingGreaterThanMs:
            scheduleIntent.onlyIfRemainingGreaterThanMs,
        }
      )
    }
    return
  }

  robotScheduler.clear(rid)
  handleGameResult(rid, result)
}
```

### 13.6 统一处理结果伪代码

```js
function handleGameResult(roomId, result) {
  if (result.action === 'round_result') {
    broadcastRoundResult(roomId, result.result)

    const nextQuestion = gameManager.createNextQuestion(roomId)
    if (nextQuestion) {
      broadcastQuestion(roomId, nextQuestion)
      robotScheduler.schedule(roomId, nextQuestion.questionId)
    }
    return
  }

  if (result.action === 'match_result') {
    // 比赛已结束，不允许旧题的机器人定时器继续触发。
    robotScheduler.clear(roomId)
    broadcastMatchResult(roomId, result.result)
    roomManager.broadcastRoomState(roomId, io)
  }
}

    io.to(playerId).emit(

    )
  })
}

  const game = gameManager.getGame(roomId)

  game.players.forEach((playerId) => {
    io.to(playerId).emit(
      'game:matchResult',
      gameManager.buildMatchResultPayload(roomId, playerId, result)
    )
```

### 13.7 游戏清理与机器人定时器的生命周期

`roomManager.clearGame(roomId)` 与 `robotScheduler.clear(roomId)` 必须作为同一个生命周期动作考虑，避免游戏已经取消或房间已经删除后，旧定时器仍然提交机器人答案。

推荐在 `handler.js` 内统一封装：

```js
/**
 * 清除房间游戏以及与该游戏绑定的机器人定时器。
 * handler 中不再直接散落 roomManager.clearGame(roomId)。
 */
function clearGameAndRobotSchedule(roomId) {
  robotScheduler.clear(roomId)
  roomManager.clearGame(roomId)
}

function cancelGameIfActive(roomId, socketId) {
  const game = gameManager.getGame(roomId)
  if (!game || game.status !== 'playing') return

  if (game.type === 'rps') {
    // RPS 是 1v1；参与者离开即取消比赛。
    if (game.players.includes(socketId)) {
      clearGameAndRobotSchedule(roomId)
    }
    return
  }

  // 算术/默写允许其余玩家和机器人继续比赛。
  // 单个人类断线时不能提前清除仍在使用的机器人定时器。
  // 只有 roomManager 判断房间被删除、游戏被取消，或比赛已经结束时才清除。
}

function handleRoomRemoved(roomId) {
  // roomManager.handleDisconnect / leave 的返回结果确认房间已删除后调用。
  robotScheduler.clear(roomId)
}
```

必须覆盖的清理时机：

- 新比赛覆盖非 playing 的旧游戏之前。
- RPS 参与者离房或断线导致比赛取消时。
- 房间被删除时。
- 比赛进入 `match_result` 时。
- 服务关闭或测试 teardown 时调用 `clearAll()`。

算术/默写中若还有玩家继续比赛，单个玩家断线不能误清定时器；这是清理逻辑与当前行为兼容的边界。

## 16. 返回结果约定

所有 `submitInput` / `handleRobotInput` 返回统一 action 结构。

### 16.1 error

```js
{
  action: 'error',
  message: '你不是本局玩家',
}
```

### 16.2 waiting

RPS 等待对手：

```js
{
  action: 'waiting',
  reason: 'waiting_opponent',
}
```

算术/默写答错：

```js
{
  action: 'waiting',
  ack: {
    questionId: 'q_...',
    correct: false,
    correctAnswer: 'music room',
    yourAnswer: 'muaic room',
  },
}
```

### 16.3 round_result

```js
{
  action: 'round_result',
  result: {
    gameType: 'spelling',
    round: 2,
    questionId: 'q_...',
    correctAnswer: 'music room',
    winner: 'socketA',
    scores: {
      socketA: 1,
      __robot__: 0,
    },
    answeredBy: {
      socketA: 'music room',
    },
  },
}
```

### 16.4 match_result

```js
{
  action: 'match_result',
  result: {
    gameType: 'arithmetic',
    matchWinner: 'socketA',
    scores: {
      socketA: 5,
      __robot__: 3,
    },
    ranking: [],
    history: [],
  },
}
```

## 17. 推荐实施顺序

为了让重构风险可控，建议按以下顺序实施：

1. 新建 `server/src/socket/games/` 目录。
2. 新建 `BaseGameMode.js`，只放基础状态和辅助方法。
3. 新建 `RpsGameMode.js`，迁移 RPS 纯规则。
4. 新建 `gameRegistry.js`，先只注册 `rps`。
5. `gameManager.submitMove` 改为调用 `RpsGameMode`，并通过 `toLegacyResult` 保持旧平铺返回格式，保证 RPS 测试通过。
6. 新建 `QuizGameMode.js`。
7. 新建 `ArithmeticGameMode.js`，迁移算术题生成、提交、结算逻辑。
8. `gameManager.submitArithmeticAnswer` / `generateQuestion` 改为兼容壳；提交结果继续保持旧平铺格式。
9. 跑算术相关单元测试和集成测试。
10. 新建 `SpellingGameMode.js`，迁移默写取词、填空、提交、结算逻辑。
11. `gameManager.submitSpellingAnswer` / `generateSpellingQuestion` 改为兼容壳；提交结果继续保持旧平铺格式。
12. 跑默写相关单元测试和集成测试。
13. 新建 `robotScheduler.js`，从 `handler.js` 抽出 `robotTimers` / `robotTimerEndAt`，实现剩余时间查询和默写定时器加速。
14. 精简 `handler.js` 中算术/默写重复广播流程，并统一游戏取消、房间删除和赛果后的定时器清理。
15. 最后整体运行 `npm test --prefix server` 和 `npm run test:integration`。

## 19. 验收条件

- 三种游戏现有玩法行为保持兼容。
- `handler.js` 不再直接承载大量游戏规则分支。
- 新增游戏模式时，不需要继续扩写一个巨大的 `gameManager.js`。
- 算术和默写共享抢答类流程，减少重复。
- 机器人定时器在开局、下一题、答对、赛果、离房、断线时都能正确清理或重建。
- 默写所有人类答错后的 5 秒加速规则保持不变。
- 旧 public API 兼容壳继续返回平铺结构，新统一入口使用 `{ action, result }` 结构。
- RPS 历史记录不包含无意义的 `ranking: undefined`。
- 未配置 `config.games` 时三种游戏仍能使用默认配置正常启动。
- 现有服务端单元测试和集成测试通过。
- 客户端现有 socket 事件名和主要 payload 字段不被破坏。

## 20. 设计边界

Phase 1 不做以下事项：

- 不改客户端 UI。
- 不改变 socket 事件名。
- 不强制修改前端倒计时逻辑，倒计时配置统一放到 Phase 2。
- 不引入数据库。
- 不重写 `RoomManager`。
- 不把 `game:rematch` 泛化到算术和默写；Phase 1 保持它仅服务 RPS，算术/默写结算重赛继续使用 `game:challenge`。
- 不做管理员认证和 CORS 加固，这些属于 Phase 3。

Phase 1 可以预留但不强制完成：

- `timeLimitMs`
- `robotAnswerDelayMs`
- `config.games`

这些预留能让 Phase 2 更顺，但不要让 Phase 1 被配置系统拖住。
