# v3.6 Phase 2 房间与对局生命周期设计

## 1. 目的与适用范围

本文冻结 Phase 2 的服务端生命周期和权限契约，作为 2b–2j 的实现、测试与验收依据。规则适用于 `rps`、`arithmetic`、`spelling` 三种模式，除明确标注的模式差异外不得在 Handler 中按游戏类型建立不同的清理语义。

本文只治理当前进程内、当前 Socket 连接对应的房间和对局。刷新恢复、断线续局、跨进程恢复、持久化和动态缩减答题参赛阵容不在本阶段范围内。

## 2. 事实来源与术语

- **房间事实来源**：`roomManager`。`room.players[socketId]` 表示当前房间成员，角色归属以 `room.roles` 为准。
- **对局事实来源**：`gameManager`。当前对局只取 `room.game`，参与者以 `game.players` 为准。
- **真人**：Socket ID 不等于 `__robot__` 的玩家。
- **房间成员**：调用时仍存在于 `room.players`，且调用 Socket 的服务端 `currentRoom` 与目标房间一致的真人。
- **对局参与者**：同时是房间成员且 Socket ID 存在于当前 `game.players` 的真人；机器人属于对局阵容，但不是 Socket 事件的合法调用者或通知对象。
- **旁观者**：是当前房间成员，但不在当前 `game.players` 中。
- **在线真人参赛者**：清理快照中的真人参与者，且通知时仍存在于目标房间。
- **过期操作**：引用的对局、状态、题目或 Socket 身份已经不再是当前事实来源中的有效对象。

客户端传入的 `roomId`、`mode`、`targetId`、`questionId` 只用于定位或一致性检查，不能单独证明房间成员或对局参与者身份。

## 3. 生命周期状态

| 设计状态 | 服务端判定 | 含义 | 允许的主要转换 |
|----------|------------|------|----------------|
| 等待中 | `room.game === null` | 房间存在，但没有可操作的当前对局 | 合法挑战后进入进行中 |
| 进行中 | `room.game.status === 'playing'` | 当前阵容可以提交游戏输入；答题模式可能存在机器人定时任务 | 正常结算进入终局；合法认输或参赛者离开/断线进入等待中 |
| 终局 | `room.game.status === 'match_end'` | 赛果已产生，旧对局仅为赛果展示和重赛授权保留 | 合法 RPS 重赛进入新的进行中；合法新挑战替换旧终局；原参赛者离开/断线后清理为等待中 |

不存在独立的“回合等待”生命周期状态。RPS 等待另一方出拳、答题模式等待当前题答案，均属于进行中的 GameMode 内部状态。

若出现未知 `game.status`，所有会改变对局的操作均按非法状态拒绝；清理流程可将该异常对局收敛到等待中，但不得据此创建新局。

## 4. 通用授权与错误规则

权限校验按以下顺序执行，失败即停止，不得产生广播或状态变化：

1. 调用 Socket 已通过 `room:join` 建立 `currentRoom`；
2. 请求目标房间与 `currentRoom` 一致；
3. 房间存在，且调用 Socket 仍是该房间成员；
4. 操作要求的对局状态正确；
5. 操作要求对局参与者身份时，调用 Socket 存在于当前 `game.players`；
6. 挑战目标、模式、角色、题目等操作专属条件正确。

非法操作统一只向调用者发送一次 `game:error`，不广播错误，不修改成员、角色、模式、比分、轮次、题目、历史、对局或机器人调度。错误文案冻结如下：

| 原因 | 文案 |
|------|------|
| 未加入房间 | `请先加入房间` |
| 请求了非当前房间 | `你不在这个房间中` |
| 房间不存在或成员记录已失效 | 分别使用 `房间不存在`、`你不在这个房间中` |
| 无当前对局或状态不适用 | `没有进行中的比赛` |
| 非当前对局参与者 | `你不是本局玩家` |
| 重赛状态或授权不成立 | 使用 `没有可重赛的已结束比赛`、`你不是上一局玩家` 或 `原参赛者已离开，无法重赛` |

GameMode 继续对选择值、答案格式、重复输入和 `questionId` 做最终校验；Handler 不复制算法，但必须在调用 GameMode 前完成房间、参与者和状态授权。

## 5. 状态与权限矩阵

### 5.1 等待中

| 操作 | 合法调用者与前置条件 | 状态变化 | 通知对象 | 清理结果 | 非法调用 |
|------|----------------------|----------|----------|----------|----------|
| 挑战 | 当前房间成员；`mode` 等于服务端房间模式。RPS 调用者和目标均在当前房间、均已选真人角色且不是同一 Socket；答题模式至少有一名已选真人角色，参赛阵容由服务端角色表加机器人生成 | 创建全新 `playing` 对局；答题模式创建首题 | 仅新对局参赛者收到 `game:start`；房间收到最新 `room:state` | 创建答题模式机器人调度；无旧对局可清 | 只向调用者发送 `game:error` |
| 输入 | 无合法调用者 | 无 | 调用者收到 `game:error` | 无 | `没有进行中的比赛` |
| 认输 | 无合法调用者 | 无 | 调用者收到 `game:error` | 无 | `没有进行中的比赛` |
| 主动离开 | 当前房间成员 | 删除成员并释放角色；最后一名真人离开时删除房间 | 剩余成员收到 `player:left` 和最新 `room:state` | 不存在对局调度；房间删除时防御性清理该房间调度 | 重复离开无状态转换、无重复广播 |
| 断线 | 当前房间成员 | 与主动离开相同 | 与主动离开相同 | 与主动离开相同 | 未加入房间的断线只记录日志 |
| 重赛 | 无合法调用者 | 无 | 调用者收到 `game:error` | 无 | `没有可重赛的已结束比赛` |

### 5.2 进行中

| 操作 | 合法调用者与前置条件 | 状态变化 | 通知对象 | 清理结果 | 非法调用 |
|------|----------------------|----------|----------|----------|----------|
| 挑战 | 无；进行中对局独占房间 | 无 | 调用者收到 `game:error` | 无 | `当前房间已有进行中的比赛` |
| 输入 | 当前对局真人参与者；事件类型与当前模式相符（RPS 使用 `game:move`，答题模式使用 `game:answer`） | 交给当前 GameMode；可能等待、推进回合或进入终局 | 依现有 `game:waiting`、`game:answerAck`、`game:roundResult`、`game:question`、`game:matchResult` 语义通知当前参赛者 | 正常终局时清除机器人调度但保留 `match_end` 对局 | 旁观者、机器人身份、错误事件类型或过期输入只收到 `game:error`；GameMode 输入错误沿用其现有文案 |
| 认输 | 当前对局真人参与者 | 当前对局直接清理为等待中，不记正常赛果、不修改比分 | 其他仍在线真人参赛者收到一次 `game:forfeited`；认输者不接收该通知；房间收到最新 `room:state` | 同一入口清除当前对局和机器人调度 | 非参与者收到 `你不是本局玩家`；无对局/非 `playing` 收到状态错误；均不得影响原局 |
| 参赛者主动离开 | 当前对局真人参与者 | 先取消当前对局，再删除成员和释放角色，最终进入等待中 | 清理快照中除离开者外的所有在线真人参赛者各收到一次 `game:cancelled`；剩余房间成员收到成员/房间更新 | 同一入口清除当前对局和机器人调度 | — |
| 参赛者断线 | 当前对局真人参与者 | 与主动离开相同 | 与主动离开相同 | 与主动离开相同 | — |
| 旁观者主动离开/断线 | 当前房间非参赛成员 | 仅删除该成员并释放角色；对局保持 `playing` | 剩余房间成员收到成员/房间更新；参赛者不收到取消通知 | 不清对局、不清机器人调度 | — |
| 重赛 | 无合法调用者 | 无 | 调用者收到 `game:error` | 无 | `没有可重赛的已结束比赛` |

认输保留现有 `game:forfeited` 事件语义；目前正式 UI 只在 RPS 暴露认输入口。协议层若由答题模式参赛者发起，仍按同一“主动终止整场对局”规则处理，不动态移除参赛者继续比赛。

### 5.3 终局

| 操作 | 合法调用者与前置条件 | 状态变化 | 通知对象 | 清理结果 | 非法调用 |
|------|----------------------|----------|----------|----------|----------|
| 挑战 | 与等待中挑战相同 | 原终局经统一入口清理后创建全新 `playing` 对局 | 新对局参赛者收到 `game:start`；房间收到最新 `room:state` | 只按捕获的旧对局 ID 清旧状态/调度，不得误清新局 | 校验失败时保留原终局，不得先清理再报错 |
| 输入 | 无合法调用者 | 无 | 调用者收到 `game:error` | 无 | 过期输入不得重复结算或改分 |
| 认输 | 无合法调用者 | 无 | 调用者收到 `game:error` | 无 | 不清终局，不重复通知 |
| 原参赛者主动离开/断线 | 仍在房间的上一局真人参与者 | 清除终局，再删除成员和释放角色 | 不发送 `game:cancelled` 或 `game:forfeited`；剩余房间成员只收到成员/房间更新 | 清除旧终局和可能残留的调度 | 离开后旧 Socket 不再具有重赛权限 |
| 旁观者主动离开/断线 | 当前房间非参赛成员 | 仅删除成员并释放角色，终局保留 | 剩余房间成员收到成员/房间更新 | 不清终局 | — |
| RPS 重赛 | 调用者是上一局真人参与者；上一局类型为 RPS；所有上一局真人参与者仍在线且属于当前房间 | 原终局清理后，以相同阵容创建 ID 不同、轮次为 1、比分和出拳为空的新 `playing` 对局 | 原参赛者收到 `game:start`；房间收到最新 `room:state` | 清旧终局/调度；新局不继承旧状态 | 旁观者、成员缺失、非 RPS 或非终局均只向调用者发送 `game:error`，原终局保持不变 |

答题模式赛果页的“再来一局”继续通过新的 `game:challenge` 发起，不使用 `game:rematch`；该挑战必须重新从当前房间角色表确定阵容。

## 6. 统一清理契约

所有认输、离开、断线、终局替换和异常收敛必须调用同一个对局清理入口。入口至少接收 `roomId`、预期 `gameId`、原因和通知策略，并遵守以下顺序：

1. 读取并保存当前对局快照、真人参与者列表和通知对象；
2. 比较当前 `room.game.id` 与预期 `gameId`；不一致时视为旧清理请求，不执行任何清理或通知；
3. 清除与该旧对局绑定的机器人任务；
4. 仅在当前对局仍是预期对局时把 `room.game` 清为 `null`；
5. 按通知策略向仍在线的真人参赛者发送一次通知；
6. 由调用流程继续清理离开者成员/角色，并广播最终 `room:state`。

同一 `gameId` 的重复清理必须返回“已清理/无操作”结果，不重复通知。机器人调度也必须绑定或校验对局/题目标识，旧定时器回调不得推进新对局。

## 7. 幂等与竞态规则

- 重复认输：第一次合法转换后，后续调用只得到状态错误或被幂等忽略；不重复发送 `game:forfeited`。
- 重复离开/重复断线清理：成员已删除时不重复 `player:left`、取消通知或房间广播。
- 离开后输入：旧 Socket 不再是房间成员或参赛者，输入被拒绝，不调用 GameMode。
- 过期题目：由 GameMode 拒绝，不计分、不换题、不调整机器人任务。
- 重复有效输入：由 GameMode 的当前回合记录拒绝，不重复计分或结算。
- 旧清理与新开局交错：清理必须校验 `gameId`；旧操作不能把新局或新局机器人任务清除。
- 终局挑战或重赛：先完成全部授权和阵容校验，再清旧终局；创建新局失败时不得留下半清理状态。

## 8. LIFE 问题映射

| 问题 | 违反的当前规则 | 目标规则与验收重点 |
|------|----------------|--------------------|
| LIFE-001 | 进行中参赛者离开规则、统一清理契约 | 算术和默写与 RPS 一致：真人参赛者主动离开或断线取消整场对局；旧 `room.game` 与机器人调度清除；其他在线真人参赛者各收到一次 `game:cancelled`；成员和角色状态随后收敛 |
